# WP3: Импорт двух Excel (B3)

**Зависимости:** WP1–2. **Может идти параллельно с WP4 и WP5.**

## Цель
Локальная команда импорта исторических Excel-файлов: настройка формата файла — в конфиге, запись — только через нормализацию WP2.

## Файлы в зоне работы
- `backend/app/sources/excel_importer/` — `cli.py`, `reader.py` (openpyxl)
- `backend/config/sources_excel.yaml` — доработка секций файлов
- `backend/tests/test_excel_import.py` + тестовые xlsx в `backend/tests/data/`

## Что сделать
1. CLI: `python -m app.sources.excel_importer --config config/sources_excel.yaml [--file <путь>] [--dry-run] [--replace-batch <id>]`.
   Без `--file` — все файлы из конфига; пути относительно `backend/`.
2. Чтение: роль, лист, столбцы по конфигам WP1/WP2 (цикл, «о ком», оценки, комментарий).
3. **Идемпотентность**: ключ записи по правилу из конфига (`file_row_hash` — хеш файла + ключевых столбцов, либо `stable_id`).
   Повторный импорт того же файла не увеличивает число ответов (обновление значений допустимо).
4. **Замена партии**: исправленная версия файла без стабильных ID строк загружается как явная замена предыдущей партии
   (`--replace-batch`): старые записи партии помечаются/удаляются, новые записываются под новым batch id.
5. Отчёт в stdout (человекочитаемый) + `--report-json <путь>`: принято / пропущено / ошибки с причинами (структура из WP2).
6. Dry-run: полный прогон чтения+валидации **без записи** в БД.

## Вне зоны
Forms API (WP4), API-маршруты (WP5). Из `app/normalization` только вызов — не менять.

## Критерий готовности (BACKEND.md B3)
- Отчёт показывает принятые, пропущенные и ошибочные строки.
- Повторный импорт того же файла не увеличивает число ответов.

## Тесты
Сгенерировать 2 тестовых xlsx (openpyxl) по формату из конфига: импорт → отчёт корректен; повторный импорт → счётчик не вырос;
dry-run → БД не изменилась; файл с битой строкой (оценка вне шкалы) → строка в `skipped` с причиной, остальные приняты;
`--replace-batch` → данные старой партии заменены.
