# WP4: Интеграция форм (B4)

**Зависимости:** WP1–2. **Может идти параллельно с WP3 и WP5.**
**Внешнее условие:** доступ к двум тестовым Google Forms (создание форм + OAuth — ручная подготовка, см. чеклист ниже).

## Цель
Один рабочий коннектор для двух форм: Backend сам делает исходящие запросы (публичный адрес не нужен),
синхронизация при запуске и по интервалу, запись — только через нормализацию WP2.

## Файлы в зоне работы
- `backend/app/sources/forms_poller/` — `client.py` (Forms API), `poller.py` (цикл синхронизации), `sync_state.py`
- `backend/config/sources_forms.yaml` — dоработка (formId, question_map)
- `backend/app/main.py` — запуск poller'а в lifespan (одна точка подключения)
- `backend/tests/test_forms_poller.py`

## Что сделать
1. `client.py`: чтение ответов формы через [Forms API `forms.responses.list`](https://developers.google.com/workspace/forms/api/reference/rest/v1/forms.responses/list)
   с пагинацией; разбор структуры ответа ([reference](https://developers.google.com/workspace/forms/api/reference/rest/v1/forms.responses)) → RawRecord (WP2).
   Ключ записи: `formId + responseId` (устойчив к сортировке/удалению строк — в отличие от номера строки Sheets).
2. `poller.py`: запуск при старте + повтор по `sync.interval_seconds`; полная перечитка обеих форм (объём кейса мал);
   upsert через `normalize_and_store` (повторное чтение не создаёт дубль).
3. `sync_state.py` → таблица `SyncState` (WP1): `last_success_at`, `last_error`, время последнего успешного получения.
   **Сбой синхронизации не стирает историю** — только фиксирует ошибку и время.
4. Подключение в `main.py`: poller стартует в lifespan, если `data_mode == real` и настроен OAuth; в режиме demo — не стартует.
5. Режим без интернета: при отсутствии ключей/доступа сервис работает на сохранённой БД (критерий B6), poller логгирует причину отключения.

## Чеклист ручной подготовки (выполнить до защиты)
- [ ] Созданы две тестовые формы (стажёр, наставник) с нужными вопросами.
- [ ] OAuth: сервисный аккаунт / desktop app, scope `forms.responses.readonly`; файл client secrets вне репозитория (путь в `.env`).
- [ ] Проверить доступ к обеим формам и работу API **с ноутбука, на котором будет защита** (ограничения сети/прокси).
- [ ] Заполнить `form_id` и `question_map` в конфиге.

## Вне зоны
Sheets API / Apps Script — запасные варианты из BACKEND.md; подключать только если основной путь не проходит (решение фиксируется в отчёте).

## Критерий готовности (BACKEND.md B4)
- Новый ответ появляется в локальном API в пределах заданного интервала.
- Повторное чтение не создаёт дубль.
- При сбое видны ошибка и время последней успешной синхронизации.

## Тесты
Мок HTTP-клиента (httpx MockTransport): новый response → запись появилась; повторный вызов → без дубля;
ошибка API → `SyncState.last_error` заполнен, прежние записи на месте; пагинация (2 страницы) → все ответы учтены.
