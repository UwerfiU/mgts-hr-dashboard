# WP9: AI-анализ комментариев (B9) — этап 2

**Зависимости:** WP7 (реальные тексты), доступный способ запуска модели. **Может идти параллельно с WP8.**

## Цель
Модуль тематизации и сводок по разрешённым текстам: результат хранится отдельно от исходного ответа, с периодом, охватом и ссылками на допустимые основания.

## Файлы в зоне работы
- `backend/app/ai/` — **основа уже есть**: `llm_client.py` (OpenAI-совместимый клиент, JSON-вывод) и `comments.py`
  (промпт анализа тональности/риска + лексиконный fallback). Расширить до тематизации и сводок.
- `backend/app/analytics/` или `app/ai/store.py` — хранение результатов AI отдельно от ответов
- `backend/app/api/v1/feedback.py` — статус анализа, сводки и сигналы по тому же срезу (согласно BACKEND.md)
- `backend/.env.example` — параметры LLM

## Что сделать
1. **Выбор модели после знакомства с текстами** (решение фиксируется в отчёте): внешний OpenAI-совместимый API или локальная модель
   (на машине защиты есть LM Studio — проверить, что выбранная модель тянет объём и качество). Клиент уже абстрагирован по `MGTS_LLM_BASE_URL`.
2. Функции: тематизация комментария (категории проблем), сводка за период/срез, оценка риска. JSON-контракт результата — расширить существующий
   (`sentiment_score/label`, `risk_level`, `issues`, `summary` → + темы, период, охват).
3. **Хранение отдельно от исходного ответа**: результат привязан к срезу (период), хранит охват (сколько комментариев учтено)
   и ссылки на допустимые основания (какие ответы легли в сводку — по ключам, не полными текстами).
4. **Анонимность**: сводки не раскрывают личность; при малом охвате (`min_sample_for_insights`) — явный статус «недостаточно данных», выводы не делаются.
5. **Отказоустойчивость**: ошибка/таймаут модели не блокирует числовую аналитику (маршруты `/metrics` работают); в `/feedback` виден статус AI («unavailable» + причина), лексиконный fallback — только как последняя ступень, явно помеченный `provider`.
6. Разрешение на тексты — по `permissions.yaml`: если показ текстов запрещён, AI-анализ работает по внутренним данным, но в API отдаётся только то, что разрешено.

## Критерий готовности (BACKEND.md B9)
- На выборке комментариев команда проверяет: сводка подтверждается текстом, не раскрывает личность, нет выводов при недостатке данных.
- Ошибка модели не блокирует числовую аналитику.

## Тесты
Мок LLM-клиента: корректный JSON → сохранён результат с охватом и основаниями; мусорный/отсутствующий ответ модели → статус unavailable, `/metrics` отвечает 200;
один комментарий в срезе при `min_sample=3` → «недостаточно данных»; сводка по срезу из 5 комментариев ссылается на все 5 ключей.
