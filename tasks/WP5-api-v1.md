# WP5: API `/api/v1` и базовые расчёты (B5)

**Зависимости:** WP1–2; согласованный контракт с Frontend. **Может идти параллельно с WP3/WP4 — на фикстурах.**
**Критично для фронта:** это контракт, по которому фронтенд развивается параллельно.

## Цель
Три маршрута из BACKEND.md + выделенный модуль расчётов + JSON-фикстуры для фронтенда.

## Файлы в зоне работы
- `backend/app/api/v1/` — `meta.py`, `metrics.py`, `feedback.py`, `codes.py` (коды недоступности)
- `backend/app/analytics/` — `coverage.py`, `series.py`, `distribution.py`, `comparison.py` (отдельный модуль расчётов, B6)
- `backend/fixtures/` — JSON-фикстуры (набор в `fixtures/README.md`)
- `backend/tests/test_api_v1.py`

## Что сделать
1. **`GET /api/v1/meta`**: циклы 1–6, каталог показателей с названиями и шкалами по ролям, разрешённые псевдонимы,
   доступные категории, признаки доступности детализации и AI, режим данных (`dataMode`) и статус синхронизации (из `SyncState`).
2. **`GET /api/v1/metrics?fromMonth&toMonth&metricId[&internId|mentorId]`**:
   - `coverage` по ролям: `submitted/expected`; при неизвестном плане ответов `expected: null` (карточка не показывает процент);
   - `series`: упорядоченные точки по циклам с числом валидных наблюдений `n`; **пропущенная точка — `value: null`, не 0**;
   - `distribution`: buckets по значениям выбранного показателя;
   - `comparison` — **только для явно настроенных пар** (`comparison_pairs` из каталога): на моках — средняя разница внутри
     сопоставленных пар «стажёр × цикл» (не вычитание средних по всем ответам); если связи между людьми нет — парные расхождения недоступны.
3. **`GET /api/v1/feedback?fromMonth&toMonth[&role|categoryId|internId]`**: разрешённые к показу комментарии
   или сообщение о недоступности. (AI-статус/сводки/сигналы добавятся в WP9 тем же срезом.)
4. **Коды недоступности** (`codes.py`): «пустой срез» и «запрещённая детализация» — разные коды; ограничения действуют на сервере, а не во фронте.
5. **Идентификаторы**: `internId`/`mentorId` — непрозрачные стабильные коды. Фильтр по наставнику выбирает связанные пары «стажёр × цикл»,
   только если связь подтверждена; при её отсутствии Backend не отдаёт персональные фильтры и отклоняет такие запросы (код недоступности).
6. **Фикстуры**: один клиент фронта + две реализации (фикстуры/HTTP) — переключатель конфигурации запуска. Фикстуры повторяют контракт,
   фильтры и состояния; при ошибке Backend фронт показывает ошибку, переход на синтетику — только явным переключателем режима.

## Вне зоны
Импорт (WP3), Forms (WP4), сигналы/AI (WP8/WP9).

## Критерий готовности (BACKEND.md B5)
- Фильтры дают ожидаемый результат на общем наборе.
- Пустой срез и неподдерживаемая детализация различаются.
- Ограничения действуют на сервере.

## Тесты
На синтетике: coverage при неполной выдаче; `expected: null`; пропущенный месяц → `value: null`; comparison считается по парам (проверить ручным пересчётом);
персональный фильтр без подтверждённой связи → код недоступности (не 200 с пустым списком); фильтры fromMonth/toMonth/role/categoryId.
