# WP8: Методика сравнения и сигналы (B8) — этап 2

**Зависимости:** WP7 (реальные источники, подтверждённые пары). **Может идти параллельно с WP9.**

## Цель
Утвердить сопоставимые вопросы/шкалы, правило разницы и минимальный объём данных; для каждого сигнала — польза и следующее действие HR;
система объясняет, почему сигнал появился или почему данных недостаточно.

## Файлы в зоне работы
- `backend/app/analytics/signals.py` — **основа уже есть** (детерминированные правила из начального скелета: low_rating, rating_drop, divergence, downward_trend + negative_comment по AI). Задача — адаптировать к модели WP1 и методике.
- `backend/config/` — новые секции/файл `signals.yaml`: пороги (разница для расхождения, падение оценки, минимальный объём), включённые типы сигналов
- `backend/app/api/v1/` — отдача сигналов по срезу (через `/feedback` или отдельным блоком — согласовать с фронтом; в BACKEND.md заложено «на финале сюда можно добавить … сигналы по тому же срезу»)

## Что сделать
1. Адаптировать правила к `Submission/Answer`: источники оценок — обе анкеты, пары сравнения — из каталога (WP1/WP7).
2. Методика (зафиксировать в конфиге + отчёте):
   - какие вопросы сопоставимы и при каком совпадении шкал;
   - правило разницы (порог, напр. |Δ| ≥ 2) и направление интерпретации;
   - минимальный объём данных для сигнала (`min_sample_for_insights` из `permissions.yaml`);
   - при недостатке данных — не «тихо молчим», а явный статус «данных недостаточно» (критерий B8).
3. Каждый сигнал несёт: тип, severity, месяц/срез, **человекочитаемую причину** (что произошло с цифрами),
   **пользу для HR и следующее действие** (напр.: «запланировать разговор наставника со стажёром», «проверить нагрузку»).
4. AI-сигналы (negative_comment) — из результатов WP9; если модель недоступна, числовые сигналы работают без неё.

## Критерий готовности (BACKEND.md B8)
- На контрольных примерах команда вручную воспроизводит расчёт.
- Система объясняет, почему сигнал появился или почему данных для него недостаточно.

## Тесты
Контрольные примеры: падение на 2 балла → сигнал с причиной и цифрами; расхождение стажёр/наставник ≥ порога → сигнал;
один месяц данных → статус «недостаточно», а не сигнал; изменение порога в конфиге меняет набор сигналов без правки кода.
