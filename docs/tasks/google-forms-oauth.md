# Подключить две тестовые Google Формы к HR-дашборду через OAuth

**Результат задачи.** После отправки анкеты в Google Forms бэкенд самостоятельно читает новый ответ, сохраняет его в SQLite и отдаёт на дашборд. Повторный опрос сохраняет прежнее число анкет.

## Исходное состояние

Обе формы опубликованы. Для стажёра `TEST-01` за второй цикл уже есть два контрольных ответа. Они нужны для привязки ID вопросов и проверки расчёта.

| Анкета | Автор | Оценка роста навыков | Время отправки, МСК |
|---|---|---:|---|
| [Стажёр](https://docs.google.com/forms/d/1IX04y4qW1OFC63i9z4I5BTAuerSygq2IPK1PqyyN7ik/edit) | `TEST-01` | 4 | 21.11.2026 10:03:46 |
| [Наставник](https://docs.google.com/forms/d/1gZ4-DBtonxKuW6i8Z9BKvesuGPEOSg9aoK9pLwOd2qs/edit) | `MENTOR-01` | 3 | 21.11.2026 10:03:00 |

На выгрузках CSV дашборд уже показал 4, 3 и разницу +1 для одной пары. В `main` исправлен запуск коннектора в режиме `real`, добавлены чтение кода наставника и команда привязки вопросов. В [конфигурации форм](../../backend/config/sources_forms.yaml) пока стоят заглушки. Для сквозной проверки через Google API осталось выпустить OAuth-клиент и получить согласие аккаунта с доступом к ответам обеих анкет.

## 1. Получить доступ к ответам

- Владелец проекта Google Cloud включает **Google Forms API**, настраивает экран согласия и создаёт OAuth client ID типа **Desktop app**. Для приложения с аудиторией External в статусе Testing добавляет аккаунт, под которым будет работать пилот, в список тестовых пользователей. [Настройка Google Forms API](https://developers.google.com/workspace/forms/api/quickstart/python)
- Владелец анкет проверяет, что этот аккаунт может открыть вкладку «Ответы» обеих форм. Скачанный JSON клиента хранится локально в `backend/secrets/client_secrets.json`. Скрипт проекта запрашивает область доступа `https://www.googleapis.com/auth/forms.responses.readonly`. [Разрешения для чтения ответов](https://developers.google.com/workspace/forms/api/reference/rest/v1/forms.responses/list)

Из каталога `backend/` в окружении Python с зависимостями из `requirements-dev.txt` выполнить команду и пройти авторизацию в браузере.

```sh
python -m app.sources.forms_poller.setup_oauth --secrets secrets/client_secrets.json
```

По умолчанию токен сохраняется в `backend/secrets/forms_token.json`. Каталог `backend/secrets/` исключён из Git. JSON клиента и токен хранить только локально.

## 2. Привязать вопросы

Из `backend/` прочитать контрольные ответы штатным клиентом и сохранить кандидата конфигурации. Исходный YAML останется доступен, даже если Google отклонит запрос.

```sh
python -m app.sources.forms_poller.prepare_pilot_config > secrets/sources_forms.candidate.yaml &&
  diff -u config/sources_forms.yaml secrets/sources_forms.candidate.yaml
```

Код завершения 1 у `diff` означает, что файлы различаются. Проверить, что генератор успешно нашёл контрольный ответ каждой формы и вывел обе секции `forms`. В каждой должны быть ID вопросов цикла, кода стажёра и оценки, у наставника также `author_mentor_field`. Оценки должны ссылаться на `skill_growth` и `skill_growth_mentor` соответственно. После проверки перенести секции `forms` в `config/sources_forms.yaml`. При ошибке генератора проверить права аккаунта и наличие исходных контрольных ответов. [Код привязки](../../backend/app/sources/forms_poller/prepare_pilot_config.py)

## 3. Запустить пилот

Запустить бэкенд из `backend/` на отдельной **изначально пустой базе**. У CSV и Google API разные ключи источника, поэтому совместная загрузка одних и тех же ответов удвоит их вес в аналитике. Для первого запуска выбрать новое имя файла, для повторного опроса использовать ту же базу.

```sh
MGTS_DATA_MODE=real MGTS_DB_URL=sqlite:///data/forms-live-check.sqlite3 \
  python -m uvicorn app.main:app --host 127.0.0.1 --port 8130
```

Во втором терминале из `frontend/` запустить интерфейс с HTTP-прокси на этот бэкенд.

```sh
npm ci
VITE_DATA_MODE=http API_PROXY_TARGET=http://127.0.0.1:8130 \
  npm run dev -- --port 5188 --strictPort
```

## Приёмка

- [ ] `GET http://127.0.0.1:8130/api/v1/meta` возвращает `dataMode=real`. Для обеих записей `form:<formId>` заполнено `lastSuccessAt`, значение `lastError` равно `null`.
- [ ] Контрольные ответы проходят весь путь от API Google. В [дашборде](http://127.0.0.1:5188/) выбрать показатель «Рост профессиональных навыков» и второй цикл в обоих фильтрах. Для пилота интерфейс подписывает его «Май 2026». Ожидаются одна анкета каждой роли, оценки **4 и 3** и разница **+1** при `nPairs=1`. [Тот же срез через API](http://127.0.0.1:8130/api/v1/metrics?metricId=skill_growth&fromMonth=2&toMonth=2)
- [ ] Отправить **один новый ответ** стажёра с кодом `TEST-02`, циклом 3 и оценкой 5. После очередного опроса обновить страницу и убедиться, что в третьем цикле число анкет стажёров выросло на одну, а показатели второго цикла сохранились. Штатный интервал опроса — 120 секунд.
- [ ] Дождаться ещё одного успешного опроса обеих форм. Время `lastSuccessAt` продвинулось, количество анкет и значения метрик сохранились. В результате задачи приложить время проверки и значения до и после повторного опроса.
